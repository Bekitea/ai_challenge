# Дополнительные примеры коммитов

## Сложные случаи

### Изменение затрагивает несколько областей
Если изменения затрагивают несколько сервисов, используй наиболее значимый:
```
feat(api): добавить эндпоинт для расчета статистики
```

### Breaking changes
Если изменение несовместимо с предыдущими версиями, добавь `!` после типа:
```
feat!(api): изменить формат ответа эндпоинта /users
```

### Коммит с телом (body)
Для сложных изменений можно добавить тело коммита через пустую строку:
```
feat(auth): добавить поддержку двухфакторной аутентификации

Добавлен новый метод аутентификации с использованием TOTP.
Пользователи могут включить 2FA в настройках безопасности.
```

## Частые ошибки (как НЕ надо)

❌ `feat (auth) : добавил OAuth2` — лишние пробелы, прошедшее время
❌ `fix: Исправил баг` — заглавная буква, прошедшее время, точка не нужна
❌ `chore( dependencies ): обновил пакеты` — пробелы в скобках
❌ `FEAT(api): добавить метод` — тип должен быть в нижнем регистре
